- *Registration timeout leaves two hooks alive.* A late pump thread finds `_running` false, skips the loop and unhooks in `finally` (`hotkeys.py:291-299`).

**Still a lead, needs a measurement:** the hook thread calls `self.after(0, ...)` directly
(`hotkeys.py:251` via `gui.py:1265`). A cross-thread Tk call waits for the main thread. If the
main thread is inside `recorder.start()` or `recorder.stop()` when the chord's key-up arrives,
the hook procedure blocks, and Windows drops hooks that overrun `LowLevelHooksTimeout` (300 ms
by default). `audio.py:118` measures 264 to 577 ms to first callback, which is close. Measure
the time spent in `_hook_proc` on press and release before deciding. The fix, if wanted: the
hook puts events on a `queue.Queue` and Tk polls it.

## 6. Opinions

- N1, N2 and N5 are one design gap: the Resident cannot be told that what it holds, or is loading, is no longer wanted. A generation counter bumped by `release`, checked in `_load` and `get`, closes all three in about ten lines. Fixing them one at a time will cost more.
- The worker has no last-resort handler. Any exception outside the four caught types leaves the pill on "Transcribing..." for good. One `except Exception` at the top of `_transcribe_and_clean` that logs and sets an error status is cheap insurance in a threaded GUI.
- `save_settings` rewrites the API key to Credential Manager on every settings-window close, and logs "Stored credential" each time (`settings_store.py:114`, `credentials.py:47`). Harmless; noisy.
- The regex guard question from the first intake is unchanged: `app_prompts.py` guards user regexes, `glossary.py` does not. Not re-read this run.

## 8. Standards feedback

Proposed amendments. The file was not edited.

1. **2.9 and 2.12 overlap on Windows.** `make check` satisfies 2.9's check ("Makefile present; command named in CLAUDE.md") and fails 2.12 ("every documented command works from a clean clone") on a machine with no `make`. Proposal: 2.9 adds "the command runs on the platform the repo targets, or the docs name the prerequisite".
2. **2.8 "install on" is not "pass on".** By the plan's measurement, locked deps install on 3.14 and the suite fails at collection. Read literally, the rule wants 3.14 in the matrix, which would turn CI red for a dependency's bug. Proposal: "the newest CPython on which the locked dependencies install and the suite collects".
3. **1.1 should say how to scan the tree.** "Over the tree and the history" reads as two scans. Git mode covers every tracked file; `--no-git` walks `.venv` and ignored files. Proposal: "`gitleaks detect` in git mode; the working tree scan is for repos with untracked, unignored files".
4. **1.1 tool lookup.** `command -v gitleaks` failed while the WinGet install existed off PATH. Proposal for the skill: on Windows, also look under `%LOCALAPPDATA%\Microsoft\WinGet\Packages` before marking NOT CHECKED.
5. **The verdict has no stated threshold.** One narrow tier 2 FAIL reads here as "not yet". If that is the intent, say so in the file ("in the fold means zero tier 1 and zero tier 2 FAIL"); if not, say how many tier 2 deviations a repo may carry.
6. **Skill: same-day reruns.** `intake-YYYY-MM-DD.md` collides when a repo is re-run on the day of its first intake, which is exactly when a fix plan ends. Proposal: append `-2`, `-3`, and never overwrite a report another file cites.
7. **Missing rule, carried over:** no rule covers a known defect recorded only as a plan checkbox (the exe and S1). 2.13 covers decisions, not known breakage. Proposal: known breakage in a shipped artifact is named in the README or an issue.
