## 6. Opinions

- **The regex asymmetry was flagged in both prior intakes and left open** ("`app_prompts.py`
  guards user regexes, `glossary.py` does not"). Reading both ends this run says neither
  was right: one over-guards a non-boundary, the other under-guards a real failure. The
  fix plan resolves it toward one rule for both. The alternative — keep the guard and add
  it to glossary too — was considered and rejected because the guard does not do what it
  claims (G2) and rejects legitimate patterns.
- **The accepted ceiling after the fix:** a pathological pattern the user wrote can spend
  real time in `re.search` on the dictation worker thread (`gui.py:1404`, `:1540`), never
  the Tk thread: one slow dictation and one core, 598 ms in the measured worst case. The plan
  records that as a `ponytail:` comment at the site (3.3) rather than replacing one
  timeout with another.
- `config.py:19-21` still says "LM Studio default" beside port 1234. Fine for a public
  repo, where LM Studio is a reasonable default; on this machine it is Ollama. A comment,
  not a claim to users.
- `save_settings` still rewrites the API key to Credential Manager on every settings-window
  close and logs "Stored credential" each time. Harmless; noisy. Carried from the second
  run.

3. **New: `improve` on a rerun is scoped to the diff, never skipped.** Step 4 says run
   `improve` then `ponytail-audit`, every time. This run tried skipping `improve` on the
   grounds that two prior runs had swept the same hotspots — and the audit alone missed

   `improve` runs over `git diff <previous intake commit>..HEAD` plus any module the
   audit names, and the report says so under Not checked. Skipping it is not an option

   list names "input validation at trust boundaries". Deciding whether a regex the user
   typed into their own settings dialog, matched against their own window title, is one
   took the longest of anything in this run. Proposal: add "A trust boundary is where
   input from another principal enters. The user's own configuration, on the user's own
   machine, is not one; validation there is a UX question, not a security one."
5. **New: a guard that does not do what it claims is a bug, not taste.** G2 is a security
   measure by name that provides none. The standards say security measures are never
   trimmed as taste; they should also say a measure that cannot work is reported as a bug
   and removed or fixed, not preserved for its name.
6. **Carried: 2.9 and 2.12 on Windows** (second run, item 1) is now moot for this repo
   but the rule text is unchanged.
